# Задание 1. Разбор tsconfig.json

Откройте `tsconfig.json` в корне проекта и для каждой строки напишите
**своими словами**, что она делает. Не копируйте документацию —
объясните так, как будто рассказываете одногруппнику.

## compilerOptions
> _открывает блок с настройками именно компилятора TypeScript_

### target
> _в какую версию JavaScript компилировать код (насколько современный синтаксис можно использовать в итоговом .js)_

### module
> _какой формат модулей использовать (import/export) в скомпилированном коде_

### moduleResolution
> _как TypeScript ищет файлы при импорте, ориентируясь на современные сборщики Vite, webpack и т.п._

### strict
> _отключает строгую проверку типов в целом (главный "рубильник" всех строгих проверок)_

### strictNullChecks
> _не проверяет, может ли переменная быть null/undefined там, где это не предусмотрено_

### "noImplicitThis": false
> _не ругается, если тип this внутри функции не может быть определён явно_

### "noImplicitAny": false
> _разрешает переменным быть без явного типа (any) без предупреждений_

### "noImplicitReturns": false
> _не проверяет, что функция возвращает значение из всех веток кода (if/else)_

### esModuleInterop
> _упрощает совместимость между старым (require) и новым (import) синтаксисом модулей_

### skipLibCheck
> _не проверяет типы внутри .d.ts-файлов из библиотек — ускоряет компиляцию_

### forceConsistentCasingInFileNames
> _требует одинаковый регистр букв в именах файлов при импорте (важно для Linux/Mac, где регистр учитывается)_

### outDir
> _куда складывать скомпилированные .js-файлы (в папку dist)_

### rootDir
> _откуда брать исходные .ts-файлы (текущая папка — корень проекта)_

## include
> _какие файлы/папки включать в компиляцию (всё внутри src и tests, на любом уровне вложенности)_

## exclude
> _акие папки игнорировать при компиляции_

# Задание 1.2. Включение флагов

Для каждого пункта ниже:
1. Определите, какой флаг нужно поменять в `tsconfig.json`.
2. Внесите изменение.
3. Запустите `npm run check`.
4. Запишите результат в `task1.md`.


### 1. Строгие проверки типов
Включите опцию, которая делает `null` и `undefined` отдельными типами,
а не «совместимыми со всем». Без неё код с `null` компилируется, с ней — нет.

**Ваш ответ:** `strictNullChecks`

---

### 2. Проверка `this`
Включите опцию, которая ругается, если внутри функции используется `this`,
но функция не является методом класса (то есть `this` не определён).

**Ваш ответ:** `noImplicitThis`

---

### 3. Неявный `any`
Включите опцию, которая ругается, если переменная получает тип `any`
автоматически (например, функция без аннотаций параметров).

**Ваш ответ:** `noImplicitAny`

---

### 4. Возврат из функции
Включите опцию, которая требует, чтобы **все** ветки функции возвращали значение,
если функция объявлена как возвращающая не-`void`.

**Ваш ответ:** `noImplicitReturns`
